# GitHub Markdown 公式显示检查与修复

检查日期：2026-11-19。范围为项目根目录与 `docs/` 中原有的全部 10 个 Markdown 文件，包括六章正文、统一框架快速版、学习大纲、README 和来源说明。

## 1. 截图中的问题与原因

在 GitHub 的第 0 章页面复现了截图中的现象：公式（0.1）的编号、公式（0.2）的部分符号被挤成竖列，行间对齐也出现异常。

页面生成的 MathML 中，带 `\tag{...}` 的公式包含 `mlabeledtr` 编号行结构。当前浏览器的原生数学排版对该结构支持不足，造成编号列与公式列布局异常。MathJax 的官方说明指出，MathML Core 不包含 `mlabeledtr`，原生 MathML 对部分表格对齐属性的支持也有限。参见 [MathJax 原生 MathML 输出说明](https://docs.mathjax.org/en/latest/output/mathml.html)。

GitHub 支持数学公式，但支持 LaTeX 输入并不保证所有编号和对齐组合在各浏览器中都能正常显示。参见 [GitHub 数学表达式文档](https://docs.github.com/en/get-started/writing-on-github/working-with-advanced-formatting/writing-mathematical-expressions)。

本次 UTF-8 检查没有发现 Unicode 替换字符 `U+FFFD`。此外发现了 3 处实际的控制字符错误：原本应为 `\tau` 的位置写成了 Tab 加 `au`。这些位置会丢失希腊字母，需要直接修正源码。

在线上逐章核验时，还发现当前 GitHub 渲染器直接报出 `The following macros are not allowed: operatorname`。这类公式在本地 MathJax 中可以解析，但在线上被拒绝。该现象是本次实际页面观察，不能据此认为所有 MathJax 环境都禁用该命令。六章正文和快速版共替换了 101 处 `\operatorname` 或其星号形式，改用 `\mathop{\mathrm{...}}\nolimits`，需要上下限位置的形式使用 `\limits`，保留运算符的含义和排版类别。

## 5. 后续统一编写规范

### 5.1 编号放在数学块外

保留稳定锚点，使用普通文本显示编号。以下为源码示意，围栏类型为 `text`，不会作为本报告中的真实公式再次解析。

````text
<a name="eq-example"></a>

**公式（示例）**

```math
\begin{aligned}
p(x)&=\int k(x\mid z)\,\mu(\mathrm{d}z),\\
s(x)&=\nabla_x\log p(x).
\end{aligned}
```

由 [公式（示例）](#eq-example) 得到下一步结论。
````

需要多行对齐时，在数学围栏内使用 `aligned`。不要再加入 `\tag`、`\label` 或 `\notag`。多个需要独立引用的公式分别设置编号、锚点和数学块。

### 5.2 行内公式保持单行

```text
正确示意：生成时间为 $`\tau=1-t`$。
```

文字段落可以换行，每一个行内公式的开始与结束分隔符应位于同一源码行。复杂推导优先放入独立公式块。

### 5.3 表格中避免裸竖线

条件概率优先使用 `\mid`，绝对值使用 `\lvert` 和 `\rvert`，范数使用 `\lVert` 和 `\rVert`。这样可以避免 Markdown 表格将公式中的竖线当作列分隔符。

### 5.4 从 LaTeX 转换后再检查

自动转换文本时，尤其要检查 `\t`、`\n`、`\b` 等序列是否被程序当作 Tab、换行或退格。生成 Markdown 后先运行检查脚本，再查看 GitHub 页面。LaTeX/PDF 中可用的编号与环境组合，需要按网页排版规范另行处理。

### 5.5 运算符使用已核验的基础写法

```text
协方差：\mathop{\mathrm{Cov}}\nolimits(X,Y)
散度：\mathop{\mathrm{div}}\nolimits a
最小化解：\mathop{\mathrm{arg\,min}}\limits_{x} F(x)
```

本仓库的 GitHub 阅读版采用这些写法，避免当前线上渲染器拒绝 `\operatorname`。若后续 GitHub 更新渲染规则，应重新核验页面，再决定是否调整规范。
